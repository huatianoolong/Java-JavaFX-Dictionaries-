Part I

OOP Foundation

01 · Classes, objects & referencesA class is a blueprint; an object is an instance; a variable holds a reference to it.
public class Dog {
    String name;            // field (state)
    void bark(){ System.out.println(name + " woofs"); }  // method (behaviour)
}
Dog d = new Dog();          // 'new' builds the object; d holds a reference
d.name = "Rex";  d.bark();
What you can doModel real things as classes; create many independent objects from one class; pass objects to methods; store them in arrays/collections. A reference can be reassigned or set to null (no object).
Exam trap — pass by valueJava is always pass-by-value. For an object, the reference is copied: a method can change the object's fields (visible to caller), but reassigning the parameter to a new object does not affect the caller's variable.
02 · Encapsulation & access modifiersHide data, expose controlled access.
public class Account {
    private double balance;                      // hidden
    public double getBalance(){ return balance; }
    public void deposit(double a){ if (a>0) balance += a; }  // validates
}
ModifierClassPackageSubclassWorld
private✔✘✘✘
(default)✔✔✘✘
protected✔✔✔✘
public✔✔✔✔
What you can doMake fields private + add getters/setters so you can validate, compute, log, or change internals later without breaking callers. Expose only what others need.
03 · Constructors & thisInitialise a new object.
public class Point {
    int x, y;
    public Point(){ this(0,0); }              // chains to the other constructor
    public Point(int x, int y){ this.x=x; this.y=y; }   // 'this' = current object
}
  • Same name as class, no return type. If you write none, Java adds a default no-arg one; write any and that freebie vanishes.
  • Overload constructors with different parameter lists. this(...) calls another (must be first statement).
  • Init order: static blocks (once) → instance fields/blocks → constructor body.
What you can doOffer several ways to build an object (full args, defaults), centralise setup with this(...) chaining, and guarantee an object is valid the moment it exists.
04 · static & finalstatic = belongs to the class; final = can't change/override.
class Counter {
    static int count = 0;               // ONE copy shared by all objects
    final int id;                        // assigned once, then constant
    static final double PI = 3.14159;    // a true constant
    Counter(){ id = ++count; }
    static int total(){ return count; }  // call as Counter.total()
}
Onstaticfinal
variableShared class variable (one copy)Constant after assignment
methodCalled on class; no thisCan't be overridden
class(nested only)Can't be subclassed (e.g. String)
What you can doUse static for shared counters, factory/utility methods (Math.max), and constants. Use final to lock values, prevent overriding, and make immutable classes.
05 · Inheritance & superA subclass reuses + extends a superclass (IS-A).
class Animal { String name; Animal(String n){ name=n; } void eat(){} }
class Dog extends Animal {
    Dog(String n){ super(n); }          // call parent ctor FIRST
    @Override void eat(){ super.eat(); /* + extra */ }
}
  • Single inheritance of classes; super(...) first statement (auto-inserted if omitted); super.m() calls parent's version.
  • Subclass inherits accessible members, can add new ones, can override methods.
What you can doShare common code in a base class; specialise in subclasses; treat subclasses uniformly through the parent type (sets up polymorphism, §07).
06 · Overloading vs overridingSame name/different params (compile-time) vs redefining a parent method (run-time).
OverloadingOverriding
WhereSame classSubclass
ParamsDifferent listSame list
ReturnAny (params decide)Same / covariant subtype
BoundCompile timeRun time (dynamic)
AccessAnyNot more restrictive
Exam trapReturn type alone can't overload. Overriding: can't throw broader checked exceptions, can't reduce visibility, can't override static/final/private. Use @Override so the compiler checks you.
07 · PolymorphismOne reference type, many runtime forms.
Animal a = new Dog("Rex");    // upcast: automatic & safe
a.eat();                       // runs Dog.eat() — decided at RUNTIME
if (a instanceof Dog d) d.bark();   // safe downcast (pattern matching)
What you can doWrite one method/loop that works on any subtype (Animal[] zoo, List<Shape>), and add new subtypes later without changing that code. This is the backbone of clean OOP.
DowncastSuperclass → subclass needs a cast and risks ClassCastException; guard with instanceof.
08 · The Object classEvery class extends Object — these methods exist everywhere.
MethodPurpose / override for…
toString()Readable text form (printing, logging).
equals(Object)Logical equality (default = ==).
hashCode()Hash for HashMap/HashSet.
getClass()The runtime type.
What you can doOverride toString() for debugging, and equals()+hashCode() together so your objects work correctly as map keys / set elements (§17).
Part II

Advanced OOP

09 · Abstract classesA partial class that can't be instantiated.
abstract class Shape {
    abstract double area();                 // subclasses MUST implement
    void describe(){ System.out.println(area()); }  // shared concrete code
}
class Circle extends Shape { double r; double area(){ return Math.PI*r*r; } }
  • Declared abstract; can't be new-ed. Mixes abstract + concrete methods, has fields & constructors.
What you can doProvide a half-built base: shared state + shared methods, while forcing each subclass to fill in the specifics (the "template method" idea).
10 · InterfacesA contract of capabilities.
interface Drawable {
    int LAYERS = 3;                  // implicitly public static final
    void draw();                     // implicitly public abstract
    default void show(){ draw(); }   // Java 8+ body
    static Drawable blank(){ return () -> {}; }  // Java 8+ static
}
class Square implements Drawable { public void draw(){} }
  • Methods public abstract by default; fields are constants. A class can implement many interfaces.
  • default/static methods (8), private methods (9). One abstract method = a functional interface (lambda target, §19).
What you can doDefine a capability (Comparable, Runnable, EventHandler) that unrelated classes can all provide; achieve multiple "inheritance" of type; pass behaviour as lambdas.
11 · Abstract class vs interfaceThe classic comparison.
Abstract classInterface
Join withextends (one)implements (many)
State/fieldsAnyConstants only
ConstructorsYesNo
Bodiesabstract + concreteabstract + default/static/private
Pick"A kind of X with shared data" → abstract class. "Can do X" (a capability many unrelated types share) → interface.
12 · Composition vs inheritanceHAS-A (hold an object) vs IS-A (extend a class).
// Inheritance (IS-A): a Car IS-A Vehicle
class Car extends Vehicle { }
// Composition (HAS-A): a Car HAS-A Engine — usually more flexible
class Car { private Engine engine = new Engine(); void start(){ engine.run(); } }
What you can doReuse behaviour by holding another object and delegating to it — avoids fragile deep class trees. Rule of thumb: favour composition over inheritance unless there's a true IS-A relationship.
13 · Nested classesClasses inside classes.
TypeWhat
static nestedNo outer instance needed.
innerTied to an outer instance; sees its fields.
localInside a method.
anonymousOne-off class + instance, often a listener/interface impl.
button.setOnAction(new EventHandler<ActionEvent>(){   // anonymous
    public void handle(ActionEvent e){ save(); }
});
button.setOnAction(e -> save());                       // lambda equivalent
What you can doBundle a helper class where it's used; implement listeners/handlers inline (anonymous class or lambda) without a separate file.
14 · EnumsA fixed set of named constants that can carry data.
enum Planet {
    EARTH(9.8), MARS(3.7);
    private final double g;
    Planet(double g){ this.g = g; }
    double gravity(){ return g; }
}
for (Planet p : Planet.values()) {}      // iterate
Planet x = Planet.valueOf("MARS");       // parse text
What you can doReplace "magic" int/String constants with type-safe values; attach data + methods to each constant; use directly in switch; compare with == (each is a singleton).
15 · GenericsType parameters for compile-time type safety.
class Box<T> { T v; void set(T x){ v=x; } T get(){ return v; } }
<T> T first(List<T> l){ return l.get(0); }       // generic method
class NumBox<T extends Number> {}                  // bounded
void read(List<? extends Number> src){}            // producer (upper bound)
void write(List<? super Integer> dst){}           // consumer (lower bound)
What you can doWrite one class/method that works for any type while keeping type safety (no casts). Bound types to restrict them; use wildcards to accept families of types. PECS: Producer Extends, Consumer Super.
ErasureGeneric types are erased at runtime — no new T(), no x instanceof List<String>.
16 · Records & sealed classesConcise immutable data + restricted hierarchies (modern Java).
record Point(int x, int y) {}      // auto fields, ctor, getters, equals/hashCode/toString
Point p = new Point(3,4);  int xv = p.x();   // accessor, no "get"

sealed interface Shape permits Circle, Square {}
final class Circle implements Shape {}
final class Square implements Shape {}
What you can doUse records for tidy immutable data (DTOs, map keys) with zero boilerplate. Use sealed to lock down who can extend a type, enabling exhaustive switch with no default.
17 · equals/hashCode & orderingEquality and sorting — heavy exam material.
@Override public boolean equals(Object o){
    if (this==o) return true;
    if (!(o instanceof Person p)) return false;
    return age==p.age && name.equals(p.name);
}
@Override public int hashCode(){ return Objects.hash(name, age); }

class Person implements Comparable<Person> {           // ONE natural order
    public int compareTo(Person o){ return Integer.compare(age, o.age); }
}
Comparator<Person> byName = Comparator.comparing(p -> p.name);  // MANY orders
list.sort(byName.thenComparing(p -> p.age));
ContractIf two objects are equals, their hashCode must match. equals is reflexive/symmetric/transitive/consistent; x.equals(null)=false.
What you can doMake objects usable as HashMap keys/HashSet items (override both); sort lists by a natural order (Comparable) or any custom/chained order (Comparator).
18 · Immutability & StringObjects whose state never changes — safer & simpler.
final class Money {                 // immutable recipe
    private final int cents;        // final fields
    Money(int c){ cents = c; }      // set once
    int cents(){ return cents; }    // no setters
}
String s = "hi";  s.concat("!");   // returns NEW string; s unchanged
StringBuilder sb = new StringBuilder("hi"); sb.append("!");  // mutable, efficient
  • String is immutable; literals are pooled ("a"=="a" true, but new String("a")=="a" false — use .equals).
  • Build strings in loops with StringBuilder, not +.
What you can doMake a class immutable (final class, final private fields, no setters, defensive copies) → free thread-safety, safe sharing, safe map keys.
19 · Lambdas & functional interfacesPass behaviour as a value — powers JavaFX events & bindings.
// a functional interface = exactly ONE abstract method
Runnable r = () -> System.out.println("go");
Comparator<String> byLen = (a, b) -> a.length() - b.length();
button.setOnAction(e -> save());           // EventHandler lambda

// method references — shorthand for a lambda that just calls one method
list.forEach(System.out::println);
names.sort(String::compareToIgnoreCase);
Built-in interfaceShape
Runnable() -> void
Supplier<T>() -> T
Consumer<T>T -> void
Function<T,R>T -> R
Predicate<T>T -> boolean
What you can doReplace bulky anonymous classes with one line; pass functions to methods (event handlers, list filters, comparators); read JavaFX code (e -> ... everywhere).

JavaFX Basics

20 · Architecture overviewApplication → Stage → Scene → Node tree.
Stage        // the WINDOW
  Scene      // the content inside one window
    root     // a single root Node...
      ...    // ...holding the whole UI tree (the "scene graph")
  • A Stage holds one Scene; a Scene holds one root Node; everything visible is a Node.
  • JavaFX since JDK 11 is a separate library (add javafx-controls, javafx-fxml via Maven).
What you can doBuild any desktop UI by nesting nodes; swap the Scene's root to "navigate pages"; open extra Stages for dialogs (§26).
21 · Application lifecycleinit → start → stop, and the UI thread rule.
public class App extends Application {
    @Override public void init(){ /* bg thread, NO UI here */ }
    @Override public void start(Stage stage){      // UI thread — build UI
        stage.setScene(new Scene(new StackPane(new Label("Hi")), 400, 300));
        stage.setTitle("Demo");  stage.show();
    }
    @Override public void stop(){ /* cleanup */ }
    public static void main(String[] a){ launch(a); }
}
Exam trap — two threadsOnly the JavaFX Application Thread may touch live UI. init() runs on another thread (no UI there). For background work, hop back with Platform.runLater(...) (§46).
22 · Scene graph & NodeEverything visible is a Node in a tree.
VBox box = new VBox(10);
box.getChildren().addAll(new Label("A"), new Button("B"));  // add children
box.getChildren().remove(0);

node.setVisible(false);   // hidden but KEEPS layout space
node.setManaged(false);   // layout ignores it
node.setDisable(true);    // greyed out, ignores input (cascades)
node.getStyleClass().add("card");   node.setId("save");      // CSS hooks
  • One node has one parent — adding it elsewhere removes it from the old parent.
  • Controls (Button, etc.) manage their own children — use their content API, not getChildren().
What you can doAdd/remove/reorder children live (the pane re-lays-out automatically); show/hide, disable, style, move, rotate, scale, and fade any node via its universal properties.

25 · FXML & controllersSeparate layout (FXML) from logic (controller).

28 · try / catch / finallyWrap risky code, handle, clean up.
try {
    int x = Integer.parseInt(text);
} catch (NumberFormatException e) {            // specific first
    System.out.println("Bad number: " + e.getMessage());
} catch (IllegalStateException | ArithmeticException e) {  // multi-catch
    log(e);
} finally {
    System.out.println("always runs");          // cleanup
}
  • Most specific catch first. Multi-catch types can't be parent/child of each other.
  • finally always runs (except System.exit()/crash); avoid return inside it (it overrides).
What you can doRecover from failures, give friendly messages, retry, and guarantee cleanup (close files, release locks) regardless of success or failure.
29 · throw / throws & custom exceptionsRaise, declare, and define your own.
void withdraw(double a) throws InsufficientFundsException {   // declare
    if (a > balance) throw new InsufficientFundsException("low");  // raise now
}
class InsufficientFundsException extends Exception {
    InsufficientFundsException(String m){ super(m); }
}
try { lowLevel(); }
catch (IOException e){ throw new ServiceException("failed", e); }  // chaining
What you can doSignal a problem to the caller (throw), document it (throws), define meaningful domain exceptions, and wrap a low-level cause while keeping its stack trace (getCause()).
30 · try-with-resourcesAuto-close resources — no leaks.
try (BufferedReader br = new BufferedReader(new FileReader("data.txt"))) {
    String line = br.readLine();
} catch (IOException e) { e.printStackTrace(); }
// br.close() called automatically, even on exception, before catch/finally
  • Resource must implement AutoCloseable; multiple are closed in reverse order.
What you can doOpen files/streams/connections without ever forgetting to close them — replaces the error-prone manual finally { x.close(); }.
31 · Common exceptions & rulesThe ones you'll be asked to identify.
ExceptionWhen
NullPointerExceptionMember access on null.
ArrayIndexOutOfBounds…Index < 0 or ≥ length.
ArithmeticExceptionInteger ÷ 0.
NumberFormatExceptionparseInt on bad text.
ClassCastExceptionInvalid downcast.
IOExceptionI/O fails (checked).
Best practiceCatch specific types; never swallow silently; don't use exceptions for normal flow; clean up with try-with-resources; include a clear message.

33 · Console inputScanner (easy) or BufferedReader (fast).

34 · Reading filesLine by line or all at once.

36 · NIO.2 — Path & FilesThe modern, cleaner file API.

37 · SerializationSave/restore whole objects as bytes.
class User implements Serializable {        // marker interface
    private static final long serialVersionUID = 1L;
    String name;  transient String password;   // transient = NOT saved
}
try (ObjectOutputStream o = new ObjectOutputStream(new FileOutputStream("u.ser"))){
    o.writeObject(user);
}
try (ObjectInputStream i = new ObjectInputStream(new FileInputStream("u.ser"))){
    User u = (User) i.readObject();          // throws IOException + ClassNotFoundException
}
What you can doPersist an object graph to disk and reload it later. Mark sensitive/derived fields transient to skip them; version with serialVersionUID.
Part VI

JavaFX Events & Binding

38 · Events & event typesAn event object describes something that happened.
TypeFires on / useful data
ActionEvent"Activated" — button, menu item, Enter in a field.
MouseEventgetX/Y, getButton(), getClickCount(), isControlDown().
KeyEventgetCode() (KeyCode), getText(), modifier checks.
ScrollEventgetDeltaY() (wheel/zoom).
DragEventDrag-and-drop data transfer.

Every event also has getSource() (node the handler is on) and getTarget() (node actually hit).

39 · Registering handlersThree ways to attach behaviour to events.
// 1. convenience — ONE handler for the common case
button.setOnAction(e -> save());
node.setOnMouseClicked(e -> System.out.println(e.getX()));
node.setOnKeyPressed(e -> { if (e.getCode()==KeyCode.ENTER) go(); });

// 2. addEventHandler — MANY, any event type
node.addEventHandler(MouseEvent.MOUSE_ENTERED, e -> highlight());

// 3. addEventFilter — runs EARLY (capture), good for vetoing input
node.addEventFilter(MouseEvent.MOUSE_PRESSED, e -> { if (locked) e.consume(); });

node.removeEventHandler(MouseEvent.MOUSE_ENTERED, ref);   // remove later
What you can doRespond to clicks, keys, scroll, drag; attach several handlers to one node; intercept input before children see it (filter); reuse a named EventHandler across controls.
40 · Propagation & consume()How an event travels the node tree.
Scene ─► VBox ─► Button     (1) CAPTURE — filters fire, root → target
                 Button      (2) TARGET
Scene ◄─ VBox ◄─ Button     (3) BUBBLE — handlers fire, target → root
  • Filters run top-down (capture); handlers run bottom-up (bubble).
  • e.consume() stops the event travelling further.
What you can doLet a parent intercept a click before a child (filter + consume), or stop a child's click from reaching ancestors (handler + consume). Mental model: filter = intercept in, handler = react out, consume = stop here.

42 · Properties & listenersObservable values — the engine behind binding.
IntegerProperty count = new SimpleIntegerProperty(0);
count.set(5);  int c = count.get();

// ChangeListener — old + new value (the common one)
slider.valueProperty().addListener((obs, oldV, newV) -> setVol(newV));
// InvalidationListener — fires when value goes stale; cheaper, no values
count.addListener(obs -> markDirty());

Types: StringProperty, IntegerProperty, DoubleProperty, BooleanProperty, ObjectProperty<T>, ListProperty<T>. Every control exposes them: textProperty(), valueProperty(), selectedProperty(), disableProperty()…

What you can doWatch any UI value and run code when it changes (listener), or wire values together so they update automatically (binding, next). Naming: xProperty() = the property; getX()/setX() = the value.
43 · Binding — the full toolkitMake one value follow others automatically. Each operation + what you can do with it.

The two core methods

label.textProperty().bind(slider.valueProperty().asString("%.0f"));
//  ^ one-way: label ALWAYS mirrors slider. Calling label.setText() now THROWS.

fieldA.textProperty().bindBidirectional(fieldB.textProperty());
//  ^ two-way: edit either, both match.

prop.unbind();        prop.isBound();   // release / check

Numeric fluent operators — build computed numbers

NumberBinding total = price.multiply(qty);            // price * qty
NumberBinding net   = total.subtract(discount).add(tax);
DoubleBinding half  = value.divide(2).negate();
NumberBinding cap   = score.add(bonus); // chain freely
Doadd subtract multiply divide negate → live totals, prices, running sums. Result recomputes whenever any input changes.

Comparisons → boolean bindings

BooleanBinding tooLow  = balance.lessThan(0);
BooleanBinding passed  = score.greaterThanOrEqualTo(50);
BooleanBinding exact   = qty.isEqualTo(target);
DogreaterThan lessThan greaterThanOrEqualTo isEqualTo isNotEqualTo → turn numbers into true/false you can feed to visibleProperty, disableProperty, styling.

Boolean logic — combine conditions

saveBtn.disableProperty().bind(nameField.textProperty().isEmpty());
loginBtn.disableProperty().bind(
        userField.textProperty().isEmpty()
        .or(passField.textProperty().isEmpty()));
errorIcon.visibleProperty().bind(valid.not());
Doand or not isEqualTo → enable/disable buttons, show/hide nodes based on several conditions at once. This is the most common real use of binding.

46 · Concurrency — Task & Platform.runLaterRun slow work off the UI thread without freezing.
Task<String> load = new Task<>() {
    @Override protected String call() throws Exception {
        return backend.fetch();        // slow work — safe here (background)
    }
};
progressBar.progressProperty().bind(load.progressProperty());
load.setOnSucceeded(e -> area.setText(load.getValue()));    // on UI thread
load.setOnFailed(e -> showError(load.getException()));       // catches exceptions
new Thread(load).start();

// quick hop back to the UI thread from any background code:
Platform.runLater(() -> label.setText("done"));
Exam trapNever touch UI from a background thread. Use a Task (bind progressProperty/messageProperty, read result in setOnSucceeded, errors in setOnFailed) or Platform.runLater.
